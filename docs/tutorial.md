# Five-minute tutorial

No MoonBit knowledge needed — programming experience in any language is enough. This tutorial builds a desktop app from scratch: a window, a button, and a counter that refreshes automatically on every click.

## 1. Install the toolchain (once)

**MoonBit toolchain**:

```sh
# Linux / macOS
curl -fsSL https://cli.moonbitlang.com/install/unix.sh | bash
# Windows (PowerShell)
irm https://cli.moonbitlang.com/install/powershell.ps1 | iex
```

<details>
<summary>Linux (Ubuntu 24.04) environment setup</summary>

The library is self-drawn and goes through native FFI, so building only needs a C toolchain, pkg-config, Python 3 (to run the library's prebuild script), plus the development packages for GTK3 / Pango / FontConfig / X11:

```sh
sudo apt install build-essential pkg-config python3 \
  libgtk-3-dev libpango1.0-dev libfontconfig1-dev libx11-dev
```

Install the rest only when you use them: embedded WebView (`@web`) needs `libwebkit2gtk-4.1-dev`; the media module (`NoahLiu/gui-media`) needs `libavformat-dev libavcodec-dev libswscale-dev libswresample-dev libavutil-dev`. If a runtime error complains about missing GTK libraries, this apt list is most likely incomplete.

</details>

<details>
<summary>Windows (10/11, x64) environment setup</summary>

You need Python 3 (to run prebuild) and the MSVC C++ toolchain (the "Desktop development with C++" workload of VS 2022 Build Tools):

```powershell
irm https://cli.moonbitlang.com/install/powershell.ps1 | iex            # MoonBit
winget install Python.Python.3.12
winget install Microsoft.VisualStudio.2022.BuildTools -e --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

On Windows, moon compiles native code **out of the box and locates the MSVC toolchain itself** — a plain shell (PowerShell / Git Bash) runs `moon run` directly; you do **not** need the "x64 Native Tools Command Prompt" or a manual `call vcvars64.bat`. (The older guidance — "must run from the Native Tools prompt", "also install CMake and ATL" — described the old libyue/CMake build chain and does not apply to the self-drawn stack.)

</details>

## 2. Create the project

```sh
moon new my_app
cd my_app
moon add NoahLiu/native-gui
```

The project generated by `moon new` needs three manual adjustments:

- **`moon.mod`: change `preferred_target = "wasm"` to `"native"`** — this library goes through native FFI and supports only the native backend (skip if the template already defaults to native).

- **Rename the entry file: `my_app.mbt` → `main.mbt`** — the current moon only recognizes a file named `main.mbt` as the program entry; the template's default file name yields `Missing main function`.

- **Replace the whole `moon.pkg` with** (note this is moon's DSL format, not JSON):

  ```
  import {
    "NoahLiu/native-gui/core",
    "NoahLiu/native-gui/ui",
  }

  pkgtype(kind: "executable")

  supported_targets = "native"
  ```

  `import` gives the code access to the library: `@ui.*` is the widget and component library plus the declarative entry (`mount_window` and the node constructors all live there), `@core.*` is the app host and reactive state (`Store` / `Signal`). `pkgtype(kind: "executable")` and `supported_targets = "native"` declare this package an executable entry that builds only for the native target.

## 3. Your first window

Replace `main.mbt` entirely with:

```moonbit
fn main {
  let count : @core.Store[Int] = @core.Store::new(0)
  let app = match @ui.mount_window(
    [
      @ui.col(
        [
          @ui.text("Hello, MoonBit!", role=@ui.Title),
          @ui.button("点我", variant=@ui.Solid, on_click=fn() {
            count.update(fn(n) { n + 1 })
          }),
          @ui.bind_label(count, fn(n : Int) -> String { "已点 \{n} 次" }),
        ],
        padding=24.0,
        row_gap=12.0,
      ),
    ],
    title="教程示例",
    width=360,
    height=220,
  ) {
    None => {
      println("本平台没有窗口后端或没有显示服务")
      return
    }
    Some(a) => a
  }
  app.run()
}
```

```sh
moon run .
```

A window appears: a title, a button, and a "已点 0 次" line. Click the button and the number ticks up on its own — that is **reactive state**: when `count` changes, the bound spot `bind_label` refreshes itself, with no "update the text on click" glue code. The UI is described declaratively as a tree of node constructors (`@ui.col([...])` / `@ui.text(...)` / `@ui.button(...)`) and mounted in one `mount_window` call; when there is no window backend or no display service, `mount_window` returns `None`, and the example exits in a structured way instead of crashing.

## 4. MoonBit syntax in brief (only what the code above uses)

| Syntax | Meaning |
|---|---|
| `fn main { ... }` | program entry |
| `let count : @core.Store[Int] = ...` | type annotation: `Store[Int]` is a box of integer state |
| `match expr { ... }` | pattern matching, branch on shape (here, unwrapping an `Option`) |
| `None => ... / Some(a) => a` | the two states of an optional value: `None` absent, `Some(x)` present |
| `fn(n) { n + 1 }` | anonymous function (lambda), passed in as a callback |
| `on_click=fn() { ... }` | labelled argument: parameters with defaults are passed by name |
| `"已点 \{n} 次"` | string interpolation, `\{expression}` embeds any value |

**Learn MoonBit properly**: the official [Chinese tutorial](https://docs.moonbitlang.com/zh-cn/latest/tutorial/index.html) ([English tutorial](https://docs.moonbitlang.com/en/latest/tutorial/index.html)); for a hands-on, learn-by-playing intro, the official [Tour of MoonBit](https://tour.moonbitlang.com) walks you through lessons in the browser.

## 5. Next steps

Once your first app runs, pick a path by goal:

**Make it look good** — the app already follows the system light/dark mode and accent colour by default; wire it with one `follow_system_theme` call:

```moonbit
handle=fn(a : @core.App) -> Unit {
  let _ = a.follow_system_theme(interval_ms=2000)
}
```

Swapping `@ui.text` / `@ui.button` for themed forms (the four `button` `variant`s, `tag` / `alert` / `card`, …) is in [components.md](components.md); stylesheets (`Style` values plus `hover` / `active` / `focus` states and transitions) are in [design.md](design.md).

**Copy from a working app** — the demo board is the material library:

```sh
git clone https://github.com/lb091188/moonbit-native-gui && cd moonbit-native-gui
moon run examples/showcase    # 14 pages: basic / form / navigation / data display / feedback / events & layout / system integration…
```

Pick a page in the left menu, write against it on the right; each page's source is its own file under `examples/showcase/pages/`, ready to copy and adapt. To start smaller: `moon run examples/hello` (a minimal window) and `moon run examples/hello-themed` (the themed widget set).

**Learn the layers** — a few documents, each covering one face:

- [declarative.md](declarative.md): describe the UI as a node tree (`Node` / `mount_window`), bind state with `Store` / `Signal` — the click counter in section 3 is its minimal form
- [layout.md](layout.md): layout styling (the flex / padding / margin fields of `Style`, and the loose parameters plus the `class` channel of `@ui.col` / `@ui.row`)
- [components.md](components.md): a reference of every widget and component's parameters and events
- [system-capabilities.md](system-capabilities.md): OS capabilities (`@sys`) — volume / app lookup / wallpaper / monitors / clipboard / power / printers…, with unified `Result` semantics

**Hit a problem** — [adaptation.md](adaptation.md) records field-tested pitfalls and root causes per platform; the tray design is in [tray.md](tray.md).

## 6. A note to contributors

The library began with one simple idea: write native desktop apps in MoonBit. It now covers self-drawn widgets, charts, Markdown, an embedded WebView and system capabilities — and there is still a lot worth doing:

- **Platform compatibility**: the mainline verification runs on Ubuntu (XFCE/GNOME/KDE) and Windows; the macOS backend is landing on the `mac` branch and is not yet merged into master — whatever you hit on a Mac is valuable input.
- **Widgets and capabilities**: un-wrapped APIs and per-platform adaptation pitfalls are all welcome as issues first.
- **Docs and examples**: the tutorial, component docs and every showcase page are open for improvement.

There is no barrier to taking part: file an issue describing a problem or idea, or send a PR directly. Before you start, just remember three things — `moon check` with zero errors and zero warnings and `moon test` all green before committing, field-tested pitfalls written into [adaptation.md](adaptation.md) together with their fixes, and one cohesive change per batch. The full process (the FFI spec for adding widgets, prebuild-hosted linking) is in the repository-root [AGENTS.md](https://github.com/lb091188/moonbit-native-gui/blob/master/AGENTS.md).
